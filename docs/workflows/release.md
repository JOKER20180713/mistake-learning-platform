# 一次版本发布

当前没有可部署产品与环境。本流程为未来发布操作清单，不属于已完成的上线证据。

1. 固定提交、制品摘要、配置版本、迁移版本和模型/提示词/索引版本；核对评审与适用检查。
2. 确认目标环境、负责人、发布窗口、依赖状态及上一可用版本。生产秘密经安全渠道注入。
3. 如需变更数据，先验证备份可恢复，执行向后兼容扩展；不可逆步骤单独说明前向修复方案。
4. 发布同一受测制品，按实际基础设施选择滚动或蓝绿；就绪后再接流量。
5. 使用合成账号验证登录、权限、任务受理、练习查看及一条安全写路径；避免向真实学生发送测试任务。
6. 检查错误、队列积压、耗时和用量。达到停止条件即暂停放量，保留现场证据。
7. 回退时恢复上一制品与兼容配置；模型与索引按配对版本切换；数据库按预定兼容/修复方案处理。
8. 记录版本、执行人、步骤、验证、结果和耗时。没有实际演练则如实写“未执行”。

外部通知、收费、邀请真实学生和公开业务上线属于具体发布范围，应在相应变更写明接收对象与执行方式；创建公开代码仓库不表示已授权这些业务动作。
