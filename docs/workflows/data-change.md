# 一次数据变更

适用：结构迁移、知识点映射修订、索引重建、留存规则调整和删除任务。当前没有数据库，执行状态不得标为已演练。

1. 列明变更对象、机构归属、历史数据形状和依赖模块，更新数据字典。
2. 明确兼容方案：先扩展新字段/结构，必要时双写和回填，验证后切读，最后移除旧结构。每一步说明重跑策略。
3. 给出旧数据样例与迁移后的期望值、记录数及不变量；同轮次修订不能增加统计次数。
4. 设计回退或前向修复；若会丢数据，先备份并验证恢复。不得把应用回退等同于数据库自动恢复。
5. 在独立测试实例执行迁移、重跑及失败注入，确认跨机构关系不被混合；保存结果。
6. 涉及向量、文件、缓存或 PDF 时列副本清单、处理顺序与补偿任务。
7. 审查后按发布流程执行，记录迁移版本、操作者与校验结果。
8. 删除流程核对全部副本；恢复备份时先重放删除清单，再允许业务访问。

真实生产记录不得直接拷贝进公开仓库或测试夹具；需要复现时制作合成数据或经核验脱敏的最小样例。
