# 状态与流程

所有状态变更由后端业务方法计算。请求提交具体操作和版本，不接受客户端任意覆盖 `status`。前提不满足返回 `STATE_CONFLICT`；版本过期返回 `VERSION_CONFLICT`，不覆盖先前结果。

## 上传与任务

上传记录：`received → recognizing → awaiting_confirmation → confirmed`。识别失败进入 `recognition_failed`，本人可重试进入 `recognizing`；内容与图像版本随确认保存。确认后修改内容创建新修订，关联分析标记为旧版本，不覆盖旧证据。

识别、分析、检索准备与导出任务共用任务状态：`queued → running → succeeded | failed | cancelled`。只有 `queued` 可直接取消；执行中的取消是请求，工作进程在安全边界确认后转为 `cancelled`。终态重试创建关联原任务的新任务，幂等标识相同不重复创建。

任务创建返回 202 和任务编号，失败信息在任务资源中返回。不要把已接受任务后发生的模型失败误写成“原请求稍后返回 503”。队列在接收前不可用才返回同步 503。

## 题目与分析

题目有 `private_draft / organization_pending / organization_published / retired` 可见状态。个人材料须具备共享授权、去除个人作答笔迹等信息并通过题库审核，才能从私有草稿提交机构审核；发布时生成独立内容版本。退役题目不进入新推荐，已发布练习仍按原快照访问。

分析结果有 `needs_evidence / needs_review / available / superseded` 状态。只有题干则为 `needs_evidence`，仅展示考点与通用易错点。依据不足或结构校验后仍有内容疑点则为 `needs_review`；可用的模型建议也必须标明来源。输入或知识点映射改变后保留原结果并标记 `superseded`，重新分析。

## 练习单与发布

`draft → published → closed → archived`；草稿可取消归档，发布后题目、顺序、答案版本和接收学生集合固定。发布前检查全部目标授权、题目可用性与完整性，任一失败不得产生部分分配。

发布后需要换题或改变接收对象时，创建新练习单版本并明确通知与旧单关系。教师可提前关闭练习，关闭后学生不得新增普通提交；错误更正通过独立修订流程办理。归档保留历史查阅权限，不代表删除数据。

首期发布采用事务版本检查；两个会话同时发布同一草稿，只有一个产生分配，另一个收到 412 或相同幂等请求的原结果。

个人练习是独立交付类型：学生确认推荐题后创建，仅以本人为接收者，创建时直接冻结版本并置为 published，同时生成本人分配。它不经过教师班级发布接口，不能接受客户端指定其他学生。其反馈、版本和下载规则与班级练习一致。

## 反馈与逐题结果

一轮反馈：`draft → submitted → reviewed`。保存草稿不计入统计；提交后保留快照。重新练习创建新轮次，修正录入错误创建同轮次新修订并记录理由。学生只能更正自己的自评或提交纠错请求，不能改写教师评阅结论；教师可在当前教学授权内更正，并保留学生原始提交。

逐题结果：`correct / incorrect / partial / unanswered / pending_review / unknown`。未选择为 `unknown`，发布后的首次反馈提交要求每题给出显式状态，`unknown` 不能通过提交校验；`unanswered` 和 `pending_review` 可提交但不进入正确率分母。

判定来源：`rule / student_self / teacher / model_suggestion`。未经确认的模型建议不直接成为正式得分。教师复核结果作为当前有效判定，原始来源仍保留。

## 错题与知识点记录

错题状态：`needs_correction → needs_review → consolidated`，后续有效错误可从后两者回到 `needs_correction`。首次答对只支持进入待复习；“已巩固”的自动判定阈值尚待 D-03 决策，之前只允许教师基于记录明确确认，记录确认依据。

同题同轮次更正不增加练习次数。正式结果改变后重新计算受影响知识点汇总，显示统计版本或更新时间；更新未完成显示“统计更新中”。统计可从有效作答修订重建，不能以页面数字作为唯一事实。

发布、取消、归档和更正必须留存行为人、机构、业务对象、前后版本、时间与操作理由。确需删除数据时执行数据生命周期规则，审计最小记录避免保留已删除的正文。
