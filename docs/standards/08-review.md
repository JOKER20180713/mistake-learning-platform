# 评审与完成定义规范

维护人：三位成员共同。规范阶段与功能阶段采用不同完成定义，不能混淆。

## 检查规则

| 编号 | 要求 | 检查方法 |
| --- | --- | --- |
| REV-01 | 每个变更说明问题、范围、依赖和验收场景；实现与规约一致 | 从 PR 能定位 proposal、design、spec 和 tasks |
| REV-02 | 变更规模与例外遵守 CONTRIBUTING，作者不能把自检写成他人评审 | 审阅记录包含独立评审人和结论；首次初始化例外单列 |
| REV-03 | 人工审查业务、权限和取舍，自动化检查格式与行为；AI 审查作为辅助证据 | 记录各检查来源，不用“AI 看过了”替代业务验收 |
| REV-04 | 要求的门禁真实执行且通过；缺命令、未部署、未运行均不算通过 | 对照检查清单与实际记录；禁止为变绿删除失败断言 |
| REV-05 | 文档、契约、状态机和数据字典随变更同步，适用处使用链接引用 | 同名字段、错误码、状态与默认值交叉核对 |
| REV-06 | 例外包含原因、范围、补偿、负责人和结束条件；不得借例外虚报完成 | 台账可检索，逾期例外在下一次受影响变更中处理 |
| REV-07 | 提交、评审、验证、部署版本能对应；记录失败与返工原因 | 按变更名可定位证据，不能只有无版本截图 |
| REV-08 | 真实数据、机密和第三方版权材料不得出现在公开仓库或审查记录 | 提交前检查文件清单与内容，发现问题停止发布相应材料 |

## 本轮文档完成定义

- 八类规范齐备，编号唯一，每条有可观察的检查动作。
- 产品范围、角色授权、状态机、接口契约、数据定义无已知矛盾。
- 具备完整的本次文档变更四文件，以及至少一份可直接导出测试的业务目标规约。
- 所有本地文档链接有效，Markdown 围栏闭合，补丁无空白错误，未包含应用代码和真实业务数据。
- 验证记录说明实际检查、未实现检查及初始化例外。没有外部成员评审时如实记录“待团队复核”。

## 后续功能完成定义

- 适用场景全部满足，失败与边界检查通过；安全越权和内容泄露项零容忍。
- API、数据、UI 与模型输出契约一致；有对应业务版本、配置和输入证据。
- 本地与 CI 规定门禁通过，独立评审完成；模型变更附评测前后对比。
- 迁移、备份恢复与回退按影响范围验证；无相关影响时记录理由，不伪造演练。
- 更新规范基线并归档变更。部署完成与开发完成分别记录，不能将合并视为上线。

任何未完成项保留为待办并说明影响。待决事项只阻止依赖它的工作，不因一个商业选项未定而阻断全部文档与工程准备。
