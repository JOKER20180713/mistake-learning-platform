# 测试规范

维护人：三人共同。规约 Scenario 是业务测试的来源；规范检查另与规则编号关联。

| 编号 | 要求 | 检查方法 |
| --- | --- | --- |
| TEST-01 | 规则计算用单元测试，授权与契约用接口测试，主路径用端到端测试；避免重复堆叠同一断言 | 每条用例注明场景/规则编号及所处层次 |
| TEST-02 | 每个场景映射至少一组正常、失败或边界用例；修复缺陷先获得可复现失败 | 对照规约与用例清单，无归属或漏场景需解释并修订 |
| TEST-03 | 独立测试数据库/存储命名空间；用例自行初始化与清理，不依赖顺序 | 随机顺序及连续两次运行，结果一致且不影响其他环境 |
| TEST-04 | 常规回归使用固定时钟、模型/队列/存储替身，不发真实付费模型请求 | 禁网运行仍通过；真实模型评测属于单独受控流程 |
| TEST-05 | 断言状态、业务码、数据变化、权限与副作用，不止长度或非空 | 刻意移除一次授权或幂等检查，对应用例必须失败 |
| TEST-06 | 判定同时遵循 API 的 HTTP 和业务码契约，错误响应不得因 200 被视为成功 | 契约表中的成功/失败组合逐项验证，禁止互相矛盾 |
| TEST-07 | 未实现、未运行、跳过与通过分别记录；失败返回非零并阻断当前变更 | 报告列出用例总数及各状态；新增跳过须有原因、负责人和解决条件 |
| TEST-08 | 对规范阈值测试下界、上界和越界；并发/幂等采用真实存储约束的集成用例 | 单文件大小上限加一、相同版本并发发布、同键异体提交可复现 |
| TEST-09 | PDF 与页面逐题核对，人工视觉验证保留输入、版本、步骤和结果，截图只作辅助 | 至少含公式、题图、长题干、多小问和跨页题目样例 |
| TEST-10 | 性能另设固定环境与负载的检查，功能单测不以机器偶发耗时作为业务失败 | 报告记录样本量、并发、硬件与 p95；阈值来自运维规范 |
| TEST-11 | AI 评测样本与阈值独立版本化，模型变更前后用同一输入比较 | 测试报告能追溯模型、提示词、样本及失败类别 |

## 拟定目录与检查入口

未来业务代码开始后建议建设 `tests/unit/`、`tests/api/`、`tests/e2e/` 和 `eval/`；当前不创建空测试冒充覆盖。命令名由工程骨架变更确定并登记到检查清单，要求本地与 CI 调用同一入口。

首批必须落地的行为：会话失效、机构及教师范围隔离、图片读取授权、反馈显式正误状态、重复提交去重、版本冲突、模型超时、检索空结果、PDF 与反馈题号一致。

## 缺陷判定

“误放行”指不具权限的请求获得内容或产生副作用；“误拒绝”指满足契约的合法请求被拒绝；“伪成功”指返回成功但规定的数据或任务不存在；“未处理故障”指堆栈泄露、无界等待或无规定结果的失败。测试必须说明属于哪一类。

不得为了通过而放宽断言、删除失败用例或把错误转成空结果。正常业务更改应先更新规约，再同步测试与实现。
