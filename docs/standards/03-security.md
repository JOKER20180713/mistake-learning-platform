# 安全开发规范

维护人：司浩鸣。业务授权唯一来源为 [角色与权限](../product/roles-and-access.md)。

| 编号 | 要求 | 检查方法 |
| --- | --- | --- |
| SEC-01 | 默认拒绝，新增接口明确公开或受保护；除仅返回运行状态的健康端点外，业务资源需认证 | 新增未登记业务入口应无法匿名访问；健康端点不得泄露连接串 |
| SEC-02 | 逐请求、逐资源校验机构与教学/个人范围，列表、数量、向量检索都遵循同一权限 | A/B 机构及同机构未授权班级交叉验证，不能泄露正文或存在性 |
| SEC-03 | 图片和 PDF 位于私有存储，通过业务对象授权下载；临时地址短期有效，不提供公开永久链接 | 另一账号或匿名重放下载请求应失败；签名 URL 若采用须测试过期 |
| SEC-04 | 采用服务端校验的会话；浏览器凭据不得存入 localStorage 或 URL，Cookie 使用 HttpOnly、Secure、SameSite | 浏览器存储、URL 和日志核验；生产只走 HTTPS；跨站写操作检查 CSRF |
| SEC-05 | 会话撤销、口令变更、机构停用下一请求即失效；密码使用成熟加盐慢哈希，不实现自制算法 | 旧会话重放必须拒绝；明文密码不能进入持久层 |
| SEC-06 | 密钥经运行环境或受控机密服务注入，不进仓库、镜像、前端与日志；泄露时先撤销轮换再清理历史 | 对待提交文件与历史进行脱敏扫描，发现可疑值不在报告重复打印 |
| SEC-07 | 参数白名单、长度与资源范围双重校验；数据库参数绑定，HTML/公式/模板按输出环境安全渲染 | 引号、标签、恶意公式指令、超长字段不能变为 SQL/脚本/命令 |
| SEC-08 | 上传校验实际文件格式、像素、大小与解码能力；服务器生成存储名，用户文件名不能成为路径 | 测试伪 MIME、路径穿越、超像素及损坏图；拒绝不能留下可公开访问文件 |
| SEC-09 | 模型输入中的题目正文、图片 OCR、检索片段均是不可信数据；禁止按其中指令改变权限或调用范围 | 含“忽略规则/读取其他机构”的样本不得触发越权行为 |
| SEC-10 | URL 拉取、回调和模型服务地址由配置及白名单控制，禁止用户传入任意内网/云元数据地址 | 注入 localhost、私有网段、重定向到内网等目标，应在请求发出前拒绝 |
| SEC-11 | 敏感字段与脱敏策略集中维护；响应只返回业务必需字段，日志禁止正文、令牌、签名 URL | 对成功、错误与调试日志抽样检查同一策略 |
| SEC-12 | 依赖锁定，新增依赖登记用途与许可；达到既定阻断等级的漏洞不得随发布绕过 | 依赖清单与锁文件比对；扫描门禁未建成不得标为已通过 |

## 会话与处置基线

首期按同站部署设计，Cookie 的 SameSite 默认 Strict；如采用跨站认证，在独立决策中说明 Lax/None、CSRF 与跳转方案，不能临时放宽。业务数据隔离不依赖客户端角色标签。

疑似密钥泄露由司浩鸣牵头撤销与轮换，相关供应商由主责成员协助；检查使用记录、替换部署配置、验证旧凭据失效后，再处理 Git 历史。公开 Issue 仅记录脱敏事件编号与处置状态。

首期授权场景必须覆盖详情、搜索、计数、附件、导出、批量发布与反馈。机构管理员也不得自动获得所有学生正文的阅读权限。
