# 后端开发规范

维护人：司浩鸣。具体框架尚未冻结，以下约束不依赖语言。接口字段与错误码唯一来源为 [API 契约](../contracts/api.md)。

| 编号 | 要求 | 检查方法 |
| --- | --- | --- |
| BE-01 | 接口层负责语法校验与映射，业务层负责授权后的业务规则和事务，数据访问层负责查询；模型、队列和文件通过适配器接入 | 检查依赖方向，业务层不得嵌入 SQL 或直接调用供应商 SDK |
| BE-02 | 接口采用 `/api/v1/` 和复数资源名，方法语义一致；新增行为先更新契约 | 路由与契约逐项核对，出现未登记响应则不通过 |
| BE-03 | JSON 成功/失败使用统一外层结构；HTTP 与业务码一致；下载文件例外仍保留请求标识响应头 | 测试正常与错误请求，不能用 HTTP 200 隐藏真实业务失败 |
| BE-04 | 类型、长度和枚举在边界校验；状态、授权和领域不变量由业务层检查，不能只靠请求结构校验 | 分别测试合法格式但不合法状态，以及非法字段类型 |
| BE-05 | 事务只含必要数据库操作；禁止事务内模型请求、PDF 渲染、文件上传和直接发消息 | 注入依赖超时，检查数据库锁不持续占用；事务回滚无外部副作用 |
| BE-06 | 业务修改与待投递事件同事务写入 Outbox；工作进程幂等消费、记录投递及重试状态 | 提交后宕机、重复投递、投递失败，确认无任务丢失和重复作答 |
| BE-07 | 每个写接口登记幂等语义；练习发布、任务创建、反馈提交要求幂等键，数据库唯一约束兜底 | 同键同体重放不新增；同键异体 409；并发重复请求仅一个效果 |
| BE-08 | 对可编辑对象使用版本条件更新，提交前检查版本；不可只用“先查后写”保证并发安全 | 两个版本相同的不同修改同时执行，后一项 412，不覆盖第一项 |
| BE-09 | 分页 `page/page_size` 默认 1/20，最大 100，超限拒绝；排序筛选白名单，稳定唯一键兜底 | 同分值/同时间记录翻页不重复；未知筛选字段返回 422，不能退化全量 |
| BE-10 | 结构变更通过迁移，查询与存储接口有明确机构范围；禁止无范围通用仓储向业务暴露 | 检查数据访问签名，跨机构测试在数据库有混合数据时仍隔离 |
| BE-11 | 必需配置缺失或非法时启动失败，选填配置才有集中登记的默认值；测试配置与生产凭据分离 | 删除必需配置启动应非零退出，缺少可选配置采用已登记默认值 |
| BE-12 | 批处理有数量上限、事务边界和补偿说明；导入确认校验预览摘要未改变 | 修改待导入文件后沿用旧确认凭据必须拒绝 |

任务创建 202 只代表被可靠接受。页面查询任务最终状态，不能把“已接收”解释为“分析成功”。失败是否重试由错误分类决定，权限失败、参数失败和内容不完整不自动反复请求。

检查目标：接口与领域用例、并发与幂等用例、适配器替身、架构审查。未来命令的建设状态见检查清单，不假定当前已有测试框架。
