# 检查入口与实施状态

状态截至规范基线 v0.1。本仓库没有应用与测试程序，以下明确区分本轮可执行检查和未来能力；本文件是检查状态的唯一登记处。

| 编号 | 检查内容 | 当前入口 | 状态与后续负责人 |
| --- | --- | --- | --- |
| CHK-DOC | 文档索引、链接、围栏、编号、文字和契约一致性 | 本轮记录中的可复现命令及人工清单 | 本轮执行，记录见下方链接；后续由三人共同维护 |
| CHK-GIT | 补丁空白与公开提交范围 | `git diff --check`、`git diff --cached --check`、`git ls-files` | 当前可运行，不能代替业务测试 |
| CHK-REMOTE | GitHub 可见性、默认分支、远端提交与文档 | `gh repo view`、`git ls-remote origin refs/heads/main` | 真实发布时执行 |
| CHK-STYLE | 格式、类型、模块依赖与静态检查 | 尚未建设 | 工程骨架变更落地；司浩鸣与孙翌程 |
| CHK-DOMAIN | 正误、版本、幂等、状态与统计规则 | 尚未建设 | 业务实现时建设；司浩鸣 |
| CHK-API | 契约、权限、文件和故障替身测试 | 尚未建设 | API 实现时建设；司浩鸣 |
| CHK-E2E | 教师发布到学生反馈主路径 | 尚未建设 | 前后端联调时建设；孙翌程 |
| CHK-AI | 固定样本质量、安全、成本与前后对比 | 只有评测协议，尚无样本或命令 | 首次模型实验前建设；周潇洋 |
| CHK-SEC | 依赖漏洞、凭据与授权回归 | 本轮人工公开内容审查；程序扫描未配置 | 工程骨架阶段登记工具版本与阻断级别；司浩鸣 |
| CHK-PERF | 约定环境下延迟、容量、限流 | 尚未建设 | 有可运行服务后建设；司浩鸣 |
| CHK-OPS | 启动、停止、迁移、备份恢复与回退 | 尚未建设 | 首次部署前演练；司浩鸣 |
| CHK-CI | 与本地同一检查入口的合并门禁 | 没有 workflow，未启用状态检查 | 工程骨架变更实际配置；不在本轮创建程序 |
| CHK-REVIEW | 非作者评审、CODEOWNERS 与分支保护 | 书面流程；账号映射待补充，未配置自动强制 | 首次初始化例外已登记；后续实际核验 |

当前记录：[2026-10-28 文档基线检查](2026-10-28-standards-baseline.md)。

## 后续建设顺序

先在技术栈确定后提供可在干净环境运行的统一检查入口，再让 CI 调用相同入口；接入必需状态检查前确认 GitHub 权限、仓库设置和失败分支有效。不得提交一个只打印“通过”的空门禁。

模型评测与发布恢复需要额外环境和预算，独立运行并附证据；它们未满足时，只能完成相应局部开发，不能将整项功能标记为可上线。
